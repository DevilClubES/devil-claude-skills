# Reference Ledger

Use this ledger when a design is influenced by external pages, screenshots, moodboards, products, articles, or demos.

## Evidence rules

1. Record only sources actually inspected in the current run.
2. Separate visible observation from inference.
3. Check asset and font licenses independently; a visual difference does not establish permission.
4. Do not copy logos, slogans, branded characters, proprietary imagery, customer claims, exact copy, or a recognizable composition.
5. Treat common patterns as context, not proof that a distinctive combination is safe to reproduce.

## Classify every borrowed idea

- `mechanism`: behavior or rule that still works after changing the subject, content, palette, and composition.
- `staging`: page-specific art direction, content arrangement, or demonstration wrapper. Replace it.
- `signature`: distinctive brand, asset, copy, composition, or interaction expression. Do not reproduce it.
- `drop`: incidental detail that does not help the brief.

Use the rename test: if changing the product, subject, palette, and layout destroys the idea, it was staging or signature—not a portable mechanism.

## Ledger template

| Source | Inspected evidence | Observation | Class | Transfer rule | Replacement or proof |
|---|---|---|---|---|---|
| URL/path | page, state, screenshot, code | specific fact | mechanism/staging/signature/drop | abstract behavior retained | original implementation, licensed asset, or removal |

## Originality gate

Before calling reference-led work ready:

- Compare the rendered result with each source at the same level of abstraction.
- Replace overlaps in signature composition, copy sequence, hero silhouette, illustration, icon family, motion choreography, and branded mockups.
- Confirm the new result expresses the current product's content, information architecture, and identity.
- Report unresolved provenance or licensing questions as blockers; do not make a legal conclusion.
