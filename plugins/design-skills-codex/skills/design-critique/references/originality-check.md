# Reference-led Originality Check

Use this rubric when an artifact was influenced by identifiable external work. This is a product-design risk review, not a legal determination.

## Build the comparison set

- List every source actually used, including screenshots, deleted assets, prompt packs, moodboards, and earlier iterations.
- Inspect visible output and underlying assets; filenames and renaming are not evidence of originality.
- Compare equivalent states and viewports where possible.

## Separate grammar from signatures

Common visual grammar includes grids, standard controls, broad type categories, conventional navigation, and familiar interaction patterns. Signature expression can include an unusual composition, copy sequence, illustration, icon family, branded mockup, distinctive motion choreography, or a rare combination of motifs.

For each overlap, record:

| Source | Current element | Overlap level | Why it matters | Required replacement |
|---|---|---|---|---|
| URL/path | exact element/state | common grammar / notable / signature risk | evidence, not conclusion | concrete original alternative |

## Originality tests

1. `Product test`: does the result express this product's real job, content, and constraints?
2. `Rename test`: would the composition still make sense if the source brand and subject disappeared?
3. `Mechanism test`: can the useful behavior survive different content, palette, geometry, and layout?
4. `Silhouette test`: are hero massing, section rhythm, focal object, and primary motion still recognizably source-shaped?
5. `Asset test`: are fonts, images, icons, video, code, and textures original, licensed, or clearly replaceable?
6. `History test`: do repository history or earlier exports contain copied material that remains publicly reachable?

Raise `red flags`, `overlaps`, or `originality risks`. Do not declare infringement or plagiarism from visual similarity alone. A readiness verdict is blocked when a signature-risk element or asset license remains unresolved.
